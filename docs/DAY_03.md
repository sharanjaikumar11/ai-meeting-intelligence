## Run

From the source repository:

```powershell
$envRoot = 'C:\Users\shara\Projects\ai-meeting-intelligence'
& "$envRoot\.venv\Scripts\python.exe" -m meeting_intelligence.summarize `
  "$envRoot\outputs\day02\speaker_demo\transcript.json" `
  --environment-root $envRoot `
  --output "$envRoot\outputs\day03\speaker_excerpt_summary"
```

This sends the transcript text, segment IDs/times, speaker labels, language, and transcription warnings to Google's Gemini API. It does not send audio, local recording paths, or the Hugging Face token. The example uses public AMI data.

The example transcript covers seconds 60-180 only. Its output is explicitly labelled an excerpt. To summarize a full meeting, pass a full-recording Day 2 transcript JSON. Source metadata determines the scope; the LLM does not choose it.

## Outputs

The new output directory receives:
- `summary.json`: meeting_summary, supported summary_statements, key_discussion_points, source interval/scope, transcript fingerprint, model/version, token usage, and warnings.
- `summary.txt`: readable summary and discussion points with quoted evidence and timestamps.

Existing output directories are never overwritten. Empty transcripts return `no_speech` without calling Gemini. Nonempty transcripts require credentials. Inputs above 120,000 serialized characters fail explicitly without truncation or sending a partial transcript. This initial limit is an application constraint, not the model's context limit.

## Validation and failure handling

- Gemini receives a simplified JSON Schema with separate summary statements and discussion points. Nested string/array length constraints caused a live 400 error, so they are enforced locally rather than sent to the server.
- Pydantic checks the response and rejects extra fields, missing evidence, and invalid structures.
- Every cited segment must exist. The application copies its full exact text as evidence; the model is not asked to reproduce quotations.
- Quotes, timestamps, and speaker IDs are added from validated source data rather than generated by the LLM.
- The canonical validated transcript is SHA-256 fingerprinted to identify the source.
- Transcript instructions are treated as conversation data in the system prompt.
- Output interrupted by a token limit, safety stop, or continuation is rejected.
- Network requests have a 60-second timeout and at most two HTTP attempts. The module does not automatically repair or retry invalid model content.
- Authentication, quota, model availability, and network failures produce actionable messages without raw request details or API keys.

Valid quotes alone do not prove a statement is factually supported. Live output must be reviewed against those quotes. Speaker-count and transcription errors from Day 2 remain relevant. The prompt asks for no personal names in summary text and cautions against repairing unclear roles, but prompt compliance is not guaranteed.
